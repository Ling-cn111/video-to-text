## 30 分钟级视频实测（2026-10-07）

- **视频**：[反向旅游 陕西铜川](https://www.bilibili.com/video/BV1QuHx6mE4e)（BV1QuHx6mE4e，27 分 18 秒，旅游纪实类）
- **transcript 来源**：字幕快路径（dm/view AI 字幕，810 句 / 7111 字，零成本）
- **分块**：3 块（内容块×2 策略实为 3 块）+ 合并，共 **4 次 LLM 调用**
- **token 用量**：输入 12,184 tok + 输出 14,627 tok
- **单视频总结成本**：**¥0.0706**（≈ 7 分钱，cache-miss 空闲价）
- **总结耗时**：32.7s（首测）/ 69.4s（复测，网络波动）

## 输出 token 结构分析（2026-10-07，用户质询核实）

**现象**：27 分钟视频总结输出 14,627 tok > 输入 12,184 tok，输出异常偏高。

**核实结论**：**输出大头是推理（思维链）token，不是内容冗余，也不是合并输入重复**。

- `deepseek-flash` 为**推理模型**：API 响应含独立 `reasoning_content` 思维链字段，
  `usage.completion_tokens_details.reasoning_tokens` 单列计费。探针实测一次小结调用：
  completion 561 tok 中 **454 tok（81%）为 reasoning**，可见 content 只占少数。
- 据此推断 27 分钟视频 4 次调用的输出（3555/7294/1994/1779 tok）大部分为思维链成本。
- **合并调用输入无重复**：仅 1,273 tok（3 块候选要点 + digest 的紧凑拼接）；
  chunk 阶段本就只输出要点 + 摘要，完整结构只在合并阶段生成一次——
  「chunk 只提取要点、合并才生成完整结构」即为当前实现。
- **计费口径**：`completion_tokens` 含 reasoning token，按输出单价（¥4/百万空闲）计费。

**后续优化参考（当前不做，单次成本仅几分钱）**：

1. 若 API 支持非推理模式参数（或切非推理模型系），关闭/缩短思维链预计省 60-80% 输出
   token，单视频成本可降至 ¥0.02-0.03 量级。
2. `max_tokens` 硬上限可兜底单次调用失控（截断 JSON 会触发重试，需与重试机制配合调参）。
3. 缓存命中（输入 ¥0.02/百万）收益有限：各块 user 内容互不相同，仅 system 前缀可共享。
